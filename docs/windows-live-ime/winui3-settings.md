# WinUI 3設定画面 — 初版必須

更新：2026-11-25（Sumiへの移行）  
決定：設定画面は初版からWinUI 3で実装する。Qt設定画面の整理だけで初版完了とはしない。

## 1. 技術とプロセス

第一候補は**WinUI 3＋C++/WinRT**。既存MozkeyのC++設定・辞書ロジックを利用しやすく、正規化ルールの二重実装を抑えられるため選ぶ。

C# WinUI 3はUI開発速度で有力な代案だが、採用する場合も同じ非同期API・保存・非常駐の条件を満たす。C++だから通常入力中のメモリが自動的に減るとは評価しない。[資料M1](references.md#microsoft)

- 設定専用の別プロセスを必要時のみ起動する。
- 最後の設定ウィンドウを閉じたら、未完了の保存を安全に処理してプロセスを終了する。
- TSF DLL、変換サーバー、候補描画へWinUIランタイムを読み込ませない。
- 設定アプリへ変換エンジン本体、システム辞書、AIモデルをリンクしない。
- 設定用の新たな常駐サービスは設けず、既存IPCを拡張する。
- ARM64とx64をそれぞれビルドする。

## 2. 初版の画面

NavigationViewによる設定カテゴリとし、通常使う項目を先に、複雑な項目を詳細へ整理する。テーマ、キーボード操作、文字拡大、読み上げに対応する。

| 画面 | 初版の機能 |
| --- | --- |
| 入力 | macOS互換プロファイル、ローマ字/かな、ライブ変換、配列とモード切替の説明 |
| 候補・外観 | 基準Macに対応する候補表示設定、ライト/ダーク、文字サイズ、候補プレビュー、アイコン |
| キー設定 | 基準プロファイルの表示・復元、割当一覧、競合検出、ユーザー変更、入出力 |
| ユーザー辞書 | 登録・検索・編集・削除、辞書単位の管理、インポート/エクスポート |
| AI補正 | Zenz ON/OFF、利用可能状態、性能プリセット、準備・エラーの説明 |
| 学習・データ | 学習設定、学習データ削除、設定バックアップ・復元 |
| 詳細 | ローマ字テーブル、移植対象と決めた詳細設定 |
| アプリについて | バージョン、配布元、更新案内、第三者ライセンス |

通常の設定、辞書登録、キー設定の途中で旧Qt画面を開く構成は初版の完成形にしない。開発中の比較用ツールとしてQtを残すことと、一般ユーザー向け設定導線をWinUIで完結させることを分ける。

上流の全詳細項目を棚卸しし、移植対象・保持のみ・提供対象外を一覧化する。未露出の設定や未知フィールドを、保存時に既定値へ戻したり消したりしない。

候補プレビューは試験文字列を使う。アプリの現在の入力本文を収集する必要はない。互換プロファイルを個別変更した場合は「カスタム」と明示し、検証済みの基準状態へ戻せるようにする。

## 3. バックエンド

WinUIのViewModel → UI非依存のC++ SettingsBackend → 既存client/IPC → 変換サーバー、という境界にする。

確認済みの既存接続には`GetConfig`、`SetConfig`、`Reload`、`SyncData`がある。Qt画面に混在する設定変換・検証は、小さいバックエンドへ分離して共有する。[上流U10/U11](references.md#upstream)

UIスレッドから同期IPC・大きな辞書I/Oを直接呼ばない。タイムアウトとキャンセルを持つ非同期操作にし、保存中・失敗・競合を画面に表示する。

BazelとMSBuildの境界は小さいnative libraryにする。同一ツールチェーンでのリンクを最初に試し、ABIやCRTが合わなければ明確なC ABIを持つ小さなDLLを使う。構造体の所有権、文字列エンコーディング、エラーコードを固定する。

## 4. 保存API

既存のIPC成功だけを、ディスクへの保存成功として扱わない。現行の通常SetConfig経路はAtomicUpdateの結果を呼出元へ返していないため、新UIでは永続化結果を扱えるようにする。[上流U3](references.md#upstream)

新規API案：

`PatchConfig(expected_revision, changed_fields)`

これは追加設計であり、現行に存在するAPI名ではない。

1. サーバー内でrevisionを照合する。
2. 最新設定へ変更した項目だけを反映する。
3. 正規化・検証を実行する。
4. atomic保存に成功したことを確認する。
5. メモリ上の設定とrevisionを更新する。
6. 保存結果、正規化済み設定、新revision、再起動が必要な項目を返す。

競合時は最新値を再取得し、他の変更を黙って上書きしない。保存失敗時は成功トーストを出さず、未保存の変更を保持する。設定ファイルとサーバーの一致を再起動後にも確認する。

初期実装は「適用」でまとめて保存する方式を基本にし、明示した項目だけ即時プレビューする。プレビュー後の取消・エラー時復元も検証する。

## 5. 辞書・キー設定

辞書の保存は既存storage層を利用して、ロック取得→読み込み→検証→保存→ロック解放→サーバー再読込の順とする。競合時は既存データを保つ。[上流U12](references.md#upstream)

大量インポートは別スレッドで実行し、件数・重複・読み形式の検証結果を確認できるようにする。書込み途中の失敗で元辞書を失わないようにする。

キー設定とローマ字テーブルは既存形式を保持する。Mac互換プロファイルはバージョン付き定義として管理し、独自変更とは区別する。キー名の表記はJIS/US配列に合わせる。

## 6. バージョンと移行

次の三つを分離する。

- アプリのリリースバージョン。
- 新製品の設定schema version。
- Mac互換操作プロファイルのrevision。

既存の`general_config.config_version`を、意味を確認せず新schema versionとして流用しない。protobufのフィールド番号を再利用しない。

移行はバックアップ→読込み→段階的変換→検証→atomic保存とする。新しい初期値は未設定項目に適用し、ユーザーの明示設定を毎回上書きしない。元Mozkeyからの移行は独立保存先への明示的なインポートにする。

## 7. 配布

WinUI 3設定アプリはunpackagedとしてMSIへ同梱する案を検証する。初回の導入試験ではWindows App SDK self-containedを候補にし、必要なCRT等も含めたclean VMでの起動を確認する。[資料M2/M3](references.md#microsoft)

self-containedは配布サイズが増え、更新を自分で届ける必要がある。framework-dependentとの比較で配布方法を固定する。同梱サイズと常駐RAMは別の指標として扱う。

## 8. 完了条件

- WinUI画面から変更→保存→画面終了→別アプリで入力へ反映→再起動後も保持が成立。
- 設定画面を閉じた後に設定プロセスが残らない。
- 基本設定・辞書・キー設定が旧Qt画面なしで完結。
- 保存失敗、競合、サーバー停止、古い設定からの移行を正しく扱う。
- 基準プロファイルの復元後、Mac互換試験へ戻れる。
- ARM64/x64、DPI拡大、ライト/ダーク、高コントラスト、キーボード操作を確認。
- 正規化・保存の規則がUIとエンジンで分岐しない。

## 9. クローズド配布に向けた依存方針

初版の一般利用者向け機能はWinUI 3で実装し、製品として出荷するQt実行ファイル・DLL・プラグイン・Qt専用設定導線の除去を目標にする。既存Qt画面は移植・比較用の開発資産として残せるが、出荷物の依存を実際に検査する。残存Qt部品がある場合、該当バージョンとモジュールのLGPL/GPL/商用条件を確認し、必要なソース提供・再リンク・通知等の義務に従う。独自WinUI 3実装のソースは原則Private側に置く。詳細は[ライセンス方針](licensing.md)。
