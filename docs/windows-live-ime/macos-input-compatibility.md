# macOS日本語入力の互換仕様

更新：2026-11-25（Sumiへの移行）  
目的：初版ではmacOS標準日本語入力の操作・表示を再現する。  
状態：資料調査済み。参照Macの実機測定は未実施。

## 1. 基準とする環境

| 項目 | 基準／状態 |
| --- | --- |
| 参照Mac | 実装開始時に選定・記録。現時点は未記録 |
| macOS版・ビルド番号 | 未記録。検索に出たバージョンで代用しない |
| 入力ソース | 日本語－ローマ字入力 |
| ライブ変換 | ON |
| Windows風のキー操作 | OFF |
| 推測候補表示 | OFF |
| キーボード配列 | JIS/USを実機で確認して固定。もう一方は別プロファイルとして検証 |
| Shiftの動作、句読点、数字・記号、入力モード | 実機の設定画面を記録 |
| タイプミス修正等 | 基準機にある項目を記録。未記録のまま動作を比較しない |
| 学習・ユーザー辞書 | 試験用の再現可能な条件を記録 |
| 基準アプリ | TextEditのプレーンテキスト。ブラウザ入力欄でも差を確認 |

Appleの公式ガイドにはライブ変換と推測候補表示が別の設定として存在する。以前の「予測を常時表示したくない」という希望は、この設定の組合せで再現する。推測候補OFFで何が表示されなくなるかは実機で記録する。[資料A2](references.md#apple)

## 2. 「完全にコピー」の判定範囲

### 一致させる対象

- キーごとの入力状態、読み、選択文節、カーソル位置。
- 候補を開く条件、初回選択、移動、閉じる条件。
- Enter/Returnによる確定範囲と、続けて押したときの改行。
- Escによる取消、読み戻し、削除の順序と対象。
- Backspace/Deleteの削除単位。
- 文節の移動・伸縮、再変換、英数・かなへの切替。
- ライブ変換や候補表示のタイミング、フォーカス、表示位置・視覚的な密度。
- 推測候補OFF時の挙動。

### 別に評価する対象

AppleとMozc/Zenzでは辞書・学習・モデルが異なるため、候補語の集合、順位、漢字選択が同じであるとは仮定しない。操作の差と変換品質の差を別の列に記録する。読みの保持、確定内容と表示の一致は、候補語の違いにかかわらず必須とする。

候補の表記や文字数が違う場合、表示座標や文節番号だけで判定せず、同じ読み範囲に対する移動・伸縮・確定の意味を比較する。初期の自動文節分割の差も別途記録する。操作上の不一致を辞書の違いとして見逃さず、残る差を「完全一致」と報告しない。

Apple独自の資産や内部コードを利用する計画ではない。挙動を記録して再現し、候補UI・アイコンの素材は独自に用意する。Windowsのフォント描画やDPIによる見え方の差は、実機比較で管理する。

## 3. 仕様を決める証拠の順序

1. 設定を固定した参照Macの記録。
2. 同じmacOS版に対応するApple公式ガイド。
3. 不一致・記載不足の調査結果。

公式説明だけで細かな挙動を埋めない。資料の版が異なる、横書き・縦書きで解釈が違う、挙動を観測できない場合は「未検証」にする。

前の提案にあった「最初のSpaceは現候補のまま一覧を開く」「Escでまず一覧だけ閉じる」「Tabで予測を開く」は、Mac仕様として確定していないため、この仕様では引き継がない。

## 4. 入力状態

各操作を少なくとも次の状態で比較する。

| 状態 | 例 |
| --- | --- |
| 未入力 | 英数／かなモードで未確定文字なし |
| ローマ字途中 | `n`、`sh`等が未解決 |
| 読み入力中 | かなになったがライブ変換表示前 |
| ライブ変換中 | 漢字表示済み、候補一覧なし |
| 候補選択中 | 一覧表示、選択文節あり |
| 文節編集中 | 境界を変更中 |
| 確定直後 | 入力は確定済み |
| 再変換中 | 確定文字列を対象に変換 |
| モード変更時 | 未確定文字がある／ない |
| フォーカス変更時 | 別入力欄・別アプリへ移動 |

エンジン内部の「Mozc結果／Zenz結果」は、上の操作の意味を変える理由にしない。同じ外部状態で同じキーを押せば、同じ操作になるようにする。

## 5. 互換性マトリクス

「資料確認」は一般的な操作の説明を確認したことを示し、実機の詳細仕様が確定した意味ではない。すべての実機欄は現在未検証。

| --- | --- | --- | --- | --- |

## 6. Windowsへのキー対応

MacのReturnはWindowsのEnter、Macの後方削除DeleteはWindowsのBackspaceとして機能を対応付ける。MacのControlやOption、英数・かな専用キーについては、キー名だけで一括置換しない。

JIS/USごとの対応表を作り、Windowsや対象アプリの予約ショートカットと競合するものを列挙する。OSによりそのまま再現できない操作は、差分として文書化する。未確定入力外で一般的なアプリの編集操作を奪わない。

## 7. 実機記録の形式

各ケースで以下を記録する。

- ケースID、OS版・ビルド、配列、設定スナップショット、アプリ版。
- 事前状態、入力キー列、キーの押下順と間隔。
- 各キー直後の読み・表示文字・選択文節・カーソル・候補一覧・選択位置。
- 確定された文字列と、その時点。
- 画面記録、測定時刻、期待状態と差分。
- 公式資料の説明と、実測で初めて確定した事項。

試験文章例：`kyouha`、`kyouhaishaniikimasu`、未解決の`n`/`sh`、英字混在、数字・記号、長文、文節再編集。通常の個人入力履歴をそのままテスト素材へ保存しない。

Windows側で同じキー列を再生し、状態・確定境界・候補表示を比較する。候補内容の差は別判定する。互換性マトリクスの未検証項目を、仮の期待値で合格にしない。

## 8. 初版の受入条件

- 基準Macの環境・設定が固定され、主要ケースの記録がある。
- キーごとの読み・確定範囲・候補選択の差が解消されている。
- 入力開始とライブ変換待機中を含め、Macにない候補の一瞬の表示がない。
- AI有効・無効でSpace/Enter/Esc/Tabの操作上の意味が変わらない。
- 見えていない候補の誤選択、入力欠落、二重確定がない。
- Macとの差が残る場合は理由と再現手順を記録し、未対応を隠さない。
- macOS版または互換プロファイルを更新した場合、該当ケースを再記録・再検証する。
